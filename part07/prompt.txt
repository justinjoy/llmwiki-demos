7교시 실습 B: 운영 문서에서 직접 호출 관계를 찾아 검토 대기 사실로 추출하라.

질문: 주문 완료 알림 처리 과정에서 어떤 서비스가 어떤 서비스의 API를 직접 호출하는가?

입력
- raw/RUN-02_v1.md: 호출 관계와 운영 조건을 찾을 원문이다.
- raw/GLOSS-01_v1.md: 서비스 이름을 표준 ID로 정규화할 용어집이다.
실행 스크립트가 두 파일의 내용을 참고 파일(JSON)의 file/content로 제공한다. 제공된 내용을 읽고 답하라. 외부 검색이나 파일 접근 도구를 호출하지 마라.

추출 절차
1. 운영 문서의 문서 번호·버전·상태·적용 대상을 읽어라. 본문에서 API 호출을 명시한 절을 찾아 호출 주체, 호출 대상, API와 호출 목적을 확인하라. 이벤트를 받는다는 설명만으로 직접 호출 관계를 만들지 마라.
2. 호출 주체와 대상을 용어집의 서비스명과 대조하여 표준 ID로 정규화하라. subject는 호출하는 쪽, object는 호출받는 쪽이다. 워커의 실행 방식과 개별 API 호출 방식을 구분하고, 직접 호출과 간접 영향 경로를 섞지 마라.
3. 두 서비스와 호출 방향을 뒷받침하는 원문을 해당 절에서 연속 문자열로 정확히 인용하라. 요약·문장 결합·생략 표시를 quote에 넣지 마라. 근거 절 번호는 실제 제목에서 확인하라.
4. 적용 범위와 호출 목적을 원문에서 찾아 scope에 요약하라. 주변 절에서 상태 확인, 지연·오류 대응, 재시도, 영향의 한계를 확인하고 note에 문서 ID·버전·절과 함께 설명하라. 운영 절차를 현재 장애 발생 사실로 단정하거나, 특정 오류의 격리 범위를 다른 장애까지 확대하지 마라.
5. 문서 상태는 원문의 상태를 읽어 기록하라. 문서 승인을 추출 사실에 대한 사람의 승인으로 간주하지 마라. 호출 관계나 출처를 확인할 수 없으면 해당 필드를 null로 두고 note에 부족한 근거를 설명하라. 검증을 통과하려고 값을 만들어내지 마라.

출력 스키마
F04_pending.json에 저장할 JSON 객체 하나만 출력하라. 다음 필드를 모두 포함하고 JSON 밖의 설명이나 코드 블록은 출력하지 마라.

실습에서 지정하는 식별자·관계 형식·검토 상태:
- assertion_id: "F04"
- snapshot_id: "S1b"
- predicate: "depends_on" (이 실습에서는 서비스 간 직접 API 호출 관계를 뜻한다)
- subject_type, object_type: "Service"
- review_status: "pending" (사람 검토 전)
- reviewer: "" (실제 검토자를 만들어내지 않는다)

원문에서 찾아 채울 값:
- subject, object: 용어집으로 확인한 호출 주체와 대상의 표준 서비스 ID
- source_id, version: 호출 근거가 있는 문서의 실제 ID와 버전
- section: 호출 근거가 있는 절을 "§번호" 형식으로 표기
- quote: 해당 절에 실제로 존재하며 호출 관계를 뒷받침하는 연속 문자열
- document_status: 원문 상태를 정규화한 값. "승인 완료"는 "approved", "검토 중"은 "draft", "리뷰 완료" 또는 "검토 완료"는 "reviewed"로 기록하고, 그 밖의 상태는 원문 그대로 기록한다.
- scope: 원문에서 확인한 적용 범위와 호출 목적의 한국어 요약
- note: 정규화·방향 판단의 근거, 주변 절에서 확인한 영향과 한계, 미확인 사항의 한국어 설명
