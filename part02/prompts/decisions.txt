제공된 원문과 타입·관계·질문 사전을 대조하여 온톨로지 반례 검토서를 작성하라.
decisions.md에 저장할 Markdown 본문만 반환하라. 파일을 직접 수정하지 말라.
이 단계에서 ARCH-01 v2 검토안 원문이 추가되었다. 승인된 v1과 상태·적용 범위를 비교하라.
다음 절을 모두 포함하라.
1. payment/pay: 이름 유사성으로 동일 개체임을 확정하지 말라. GLOSS-01은 다음 교시 자료이며 이번 입력에 없으므로 읽었다고 인용하지 말라. 병합 여부는 확인 보류로 기록하라.
2. ARCH-01 v1/v2: 문서 버전 증가와 운영 배포 변경은 다르다. 원문 상태와 절을 근거로 현재 기준과 검토안을 분리하라.
3. ledger/ledger-db: 타입을 구분할 수 있는 모델인지 점검하라. ledger-db의 개체 정보가 원문에 없다면 후보로 남기고 DB 이름만으로 같은 Service라고 병합하지 말라.
4. API와 서비스 호출: 호출 서비스→API→제공 서비스 방향과 depends_on 투영을 원문의 API 예로 설명하라. API 제공 서비스와 운영 책임 Team을 혼동하지 말라.
5. 운영 조건: 문서에 있는 담당 팀은 남기고 현재 당직자·현재 지표·실행 승인은 확인 보류로 구분하라.
각 절에 반례 / 현재 모델 점검 / 유지 또는 수정 제안 / 근거 / 남은 확인을 기록하라.
수정이 필요하면 types.csv·relations.csv·questions.csv 중 수정할 파일과 내용을 명시하라. 이미 수정했다고 쓰지 말라.
원문 링크는 이 문서에서 raw/파일명.md로 연결하라. 입력되지 않은 문서는 링크 대신 후속 확인 대상으로 이름만 기록하라.
생성 결과는 사람 검토 전의 초안으로 표시하고 검토자·검토 날짜를 꾸며내지 말라.
