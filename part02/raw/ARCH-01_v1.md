# 직영몰 주문·결제 시스템 구성

문서 번호: ARCH-01 v1  
담당: 커머스플랫폼팀  
상태: 승인 완료  
최종 수정: 2026-08-22  
적용 대상: 직영몰 카드 결제

## 1. 주문 처리 흐름

직영몰에서 카드로 결제하는 주문의 처리 흐름을 정리한다. 월말 후불 정산과 협력사 직배송은 별도 처리한다.

쇼핑몰 서버(shop)는 주문서가 접수되면 주문 서비스(order)의 POST /v1/orders를 호출한다. 주문 서비스(order)는 재고 예약과 견적 유효기간을 확인한 뒤 결제 서비스(pay)의 POST /v1/payments/authorize를 호출한다. 결제가 완료되면 주문을 확정(CONFIRMED)하고 출고 시스템에 전달한다.

응답이 늦어지면 화면에 ‘결제 확인 중’을 표시하고 기존 주문 번호로 처리 상태를 조회한다. 고객이 화면을 새로고침하더라도 결제를 다시 요청하지 않는다. 장애 추적을 위해 쇼핑몰에서 생성한 요청 ID를 주문·결제 서비스에 함께 전달한다.

## 2. 결제 내역 기록과 타임아웃

결제 서비스(pay)는 PG사의 승인 응답을 받은 뒤 원장 서비스(ledger)의 POST /v1/journal-entries를 동기로 호출한다. 결제 ID(payment_id), 가맹점 ID(merchant_id), 금액, 통화, 승인 번호를 원장에 기록한다.

중복 기록은 결제 ID와 전표 유형(entry_type)의 조합으로 확인한다. 같은 요청이 다시 들어오면 기존 처리 결과를 반환한다. 결제 ID와 전표 유형이 같은데 금액이 다르면 오류로 처리한다.

| 호출 구간 | API | 타임아웃 | 타임아웃 시 처리 |
| --- | --- | --- | --- |
| 쇼핑몰 → 주문 | POST /v1/orders | 5초 | 기존 주문 번호로 상태 조회 |
| 주문 → 결제 | POST /v1/payments/authorize | 3초 | 결제 확인 중(PAYMENT_PENDING)으로 유지 |
| 결제 → 원장 | POST /v1/journal-entries | 1.8초 | 원장 반영 대기(LEDGER_PENDING)로 저장 후 대사 큐에 등록 |

응답을 받지 못했더라도 PG사에서 이미 승인했을 수 있다. 결제를 새로 요청하기 전에 기존 결제 ID로 승인 내역을 조회한다. 각 서비스에서 독립적으로 자동 재시도하지 않고, 결제 서비스에서 확인과 재처리를 담당한다.

## 3. 운영 담당

쇼핑몰 서버와 주문 서비스는 커머스플랫폼팀, 결제 서비스와 원장 서비스는 결제정산팀에서 운영한다.

야간 장애는 SRE 당직자가 먼저 확인한다. 결제 내역을 수정하거나 재처리해야 하는 경우 결제정산팀 당직자에게 연락한다. 당직자와 연락처는 당직표에서 확인한다.
