# 원장 연동 변경안 사전 검토 요청

문서 번호: CHG-12 v1  
담당: 커머스플랫폼팀  
상태: 검토 착수 승인  
최종 수정: 2026-08-22  
적용 대상: 스테이징 검증 · 설계 리뷰 자료

## 1. 검토할 구성

주문 서비스에서 원장 반영 여부를 직접 확인하는 방안과 결제 서비스의 원장 기록을 비동기로 바꾸는 방안을 비교한다. 스테이징에서 다음 세 가지 구성의 호출 경로와 장애 영향을 확인한다.

| 구분 | 구성 |
| --- | --- |
| S1: 현행 | 쇼핑몰 → 주문 → 결제 → 원장. ARCH-01 v1 기준 |
| S2: 조회 경로 추가 | S1에 주문 → 원장 조회 경로 추가 |
| S3: 비동기 기록 검토 | S2에서 결제 → 원장 직접 호출 제거. ARCH-01 v2 검토안과 함께 확인 |

S2에서는 주문 서비스(order)가 원장 서비스(ledger)의 주문별 기록 조회 API를 직접 호출한다. 주문 서비스에 원장 쓰기 권한은 부여하지 않는다.

S3의 이벤트 전달과 원장 처리 워커는 별도 설계가 필요하다. 우선 직접 API 호출이 바뀌는 구간부터 비교한다.

## 2. 검토 항목과 제출 자료

커머스플랫폼팀과 결제정산팀은 구성별로 아래 내용을 정리해 설계 리뷰에 공유한다.

- 변경 전후 서비스 호출 경로
- 원장 장애 시 주문 처리와 알림 발송에 미치는 영향
- 조회 API의 접근 권한과 예상 호출량
- 결제 승인 내역과 원장 기록이 다를 때의 처리 방식

비교표에는 구성 번호(S1·S2·S3)를 표시한다. 알림 워커까지 포함한 현행 호출 목록은 S1b로 별도 관리하며, RUN-02의 주문 상태 조회 경로를 반영한다.

조회 API 명세와 비동기 처리 방안이 확정되면 부하·장애 시험을 진행한다. 운영 배포 일정은 시험 결과를 검토한 뒤 결정한다.
