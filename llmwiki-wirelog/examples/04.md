# S2와 S3에서 ledger에 도달하는 후보를 비교하고 pay가 왜 달라지는지 알려줘.

기준: S1b · PyreWire 1.1.2 · 교육용 자료

- **사실** S2 스냅샷에서 원장 서비스(ledger)에 도달하는 직간접 호출자 후보(upstream)는 order, pay, shop이다. [E1]
- **사실** S3 스냅샷에서 원장 서비스(ledger)에 도달하는 직간접 호출자 후보(upstream)는 order, shop이다. [E2]
- **사실** S2 스냅샷에서는 결제 서비스(pay)가 원장 서비스(ledger)의 POST /v1/journal-entries를 동기로 직접 호출하는 경로(Fact F03)가 존재하여 pay가 ledger 도달 후보에 포함된다. [E1]
- **해석** S3 스냅샷에서는 pay에서 ledger로의 직접 호출 경로가 제거되어 pay가 ledger 도달 후보에서 제외되므로 두 스냅샷 간에 pay의 포함 여부가 달라진다. [E1] [E2]
- **사실** S2와 S3 스냅샷 모두에서 주문 서비스(order)는 ledger를 직접 호출하며(Fact EXP01), shop은 order를 거쳐(Fact F01) ledger에 간접 도달한다. [E1] [E2]
- **사실** S2와 S3는 가상 설계 비교 구성으로 실제 운영 환경 배포 사실이 아니며, 도달 경로 결과는 점검 대상 후보일 뿐 실제 장애 확정이나 전파를 보장하지 않는다. [E1] [E2]

## 미확인·추가 확인
- S3 구성에서 pay의 비동기 원장 기록 처리 방식에 대한 세부 구현 사양
