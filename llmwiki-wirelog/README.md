# LLMWiki × PyreWire · 자연어 질의 데모

자유롭게 질문하면 **LLM이 검색·원문 읽기·관계 조회를 선택**하고, 실제 PyreWire 계산과 원문 근거를 이용해 답합니다. 브라우저 질문 화면, 단발 CLI, 후속 질문을 받는 터미널 대화를 제공합니다. 특정 질문의 정답을 반환하는 분기나 미리 저장된 답변을 실행 경로에 사용하지 않습니다.

## 바로 시작

프로젝트 루트에서 실행합니다. CPython 3.11~3.14, `pyrewire>=1.1.2`, 로그인된 LLM CLI가 필요합니다.

```sh
cd demos/llmwiki-wirelog
python3 -m pip install -r requirements.txt
python3 serve.py --cli agy
```

브라우저에서 **http://127.0.0.1:8765** 를 엽니다. 질문을 입력하고 `질문하기`를 누르세요. `E1` 등의 인용 버튼을 누르면 원문 절 또는 실제 관계 결과·사실 ID 경로가 펼쳐집니다. 실행 과정과 결과 JSON도 확인·저장할 수 있습니다. `Ctrl+C`로 서버를 종료합니다.

가상환경이 필요하면 설치 전에 `python3 -m venv .venv`와 `source .venv/bin/activate`를 실행하세요. 포트 충돌은 `--port 8766`으로 변경합니다. 서버는 로컬 컴퓨터에만 바인딩됩니다.

### 터미널에서 질문

```sh
python3 ask.py "원장이 지연되면 어떤 서비스를 점검해야 하나요?"
python3 ask.py "결제 서비스의 담당 팀과 현재 당직자는 누구인가요?"
python3 ask.py "S2에서 S3로 바꾸면 영향 후보가 어떻게 달라지나요?"
python3 ask.py --chat
```

대화 모드에서 `/reset`은 새 대화, `/quit`은 종료입니다. 웹의 `새 대화`도 같은 역할을 합니다. 후속 질문에는 최근 세 번의 대화를 전달하지만, 이전 답변을 새 질문의 근거로 인정하지 않고 원문·그래프를 다시 확인합니다. 브라우저를 새로고침하면 화면 대화는 초기화되며 실행 기록은 남습니다.

기본 스냅샷은 `S1b`입니다. 웹 선택 상자 또는 `--snapshot S1`으로 변경하세요. 자연어로 S2/S3 비교를 요청하면 두 스냅샷을 각각 조회할 수 있습니다.

## 질문 예시

- payment와 pay는 같은 서비스인가요? ledger-db도 원장 서비스인가요?
- 주문 확정 전에 결제를 동기로 기다리는 이유는 무엇인가요?
- 원장이 지연되면 notify도 점검해야 하나요? 알림 오류가 결제 취소로 이어지나요?
- 25분과 42분은 각각 무엇을 측정한 값인가요?
- 현재 대사 큐를 중지해도 되나요? 조건과 승인자는 누구인가요?
- ARCH-01 v2가 이미 운영에 적용되었나요?
- S2와 S3의 ledger 영향 후보를 비교해 주세요.

현재 지표·당직자 실명·실행 승인·향후 복구 시각은 자료에 없으므로 미확인으로 답해야 합니다. 질문 이해와 문장 생성에는 실제 LLM을 사용합니다. 응답마다 몇 차례 LLM 호출이 필요하므로 CLI 이용량이 발생하며, 질문과 선택된 교육자료가 해당 CLI의 모델 제공자에게 전달됩니다.

## 동작 구조

```text
질문 + 최근 대화 + 문서 목차
              ↓
LLM: 읽기 도구 선택 (JSON)
   ├─ search_documents → 위키·원문 절 키워드 검색
   ├─ read_document    → 원문 절·상태·SHA-256·근거 ID
   └─ query_graph      → PyreWire EasySession.snapshot()
              ↑                  ↓
              └──── 조회 결과·근거 ─┘
              ↓
LLM: 주장·인용·미확인 사항 작성
              ↓
인용 ID·원문 우선·구조 검증 → 답변 + 실행 기록
```

검색은 로컬 키워드 검색이며 임베딩 검색으로 가장하지 않습니다. LLM이 동의어·검색어·읽을 절을 선택합니다. 관계 질의는 미리 정의한 `upstream`, `downstream`, `direct`, `path`, `documents` 연산에 서비스와 스냅샷을 전달합니다. LLM 생성 코드를 실행하지 않습니다. 재귀 관계 계산은 **PyreWire Python API**가 담당하며 `wirelog_cli`나 `subprocess`로 엔진을 호출하지 않습니다. LLM CLI 연결에는 기존 교시와 같은 실행기를 사용합니다.

한 질문당 최대 LLM 6회, 도구 12회, 한 번에 도구 3개로 제한합니다. 반복 요청과 가짜 인용을 거부하며, CLI 오류·시간 초과·회차 소진은 실패로 기록합니다. `--timeout 180`은 LLM 호출당 제한입니다. 모든 주장은 실제 근거 ID를 가져야 하며, 위키 초안만으로 사실을 확정할 수 없습니다. 인용 존재와 구조 검사는 주장의 의미를 완전히 검증하거나 사람이 승인했다는 뜻이 아닙니다.

## 자료와 기준

이 디렉토리 안의 `data/`로 실행되며 다른 교시의 실행 결과 파일에 의존하지 않습니다.

| 위치 | 내용 |
| --- | --- |
| `data/raw/` | 최종 개정 교육자료의 원문 8개 |
| `data/wiki/` | part08에서 생성한 위키 6개, 사람 검토 대기 |
| `data/ontology/` | 타입·관계 사전, 근거를 가진 별칭·개체 |
| `data/snapshots/` | S1/S1b 승인 예시, S2/S3 설계 가정 |
| `data/manifest.json` | 배포 원문과 위키의 SHA-256 |
| `llmwiki/` | 문서 검색, 사실 검증, PyreWire 엔진, LLM 도구 루프 |
| `web/` | 별도 빌드 없이 실행되는 질문 화면 |
| `runs/` | 질문별 실제 프롬프트·응답·도구 결과·근거·답변 |

서비스 ID는 `shop`, `order`, `pay`, `ledger`, `notify`입니다. 관계 후보는 실제 장애 확정이 아닙니다. `about`은 첫 수업에서 적재한 3개 문서 링크이며 전체 문서 검색 범위와 다릅니다. `S1b`의 알림 경로와 `S2/S3` 설계 가정을 섞지 않습니다.

질문 기능은 읽기 전용입니다. 답변은 `runs/`에 저장하며 원문·위키·승인 사실을 자동 변경하지 않습니다. 자체 자료로 확장하려면 원문 메타데이터·절 구조를 유지하고, 승인 사실의 출처·인용·상태를 함께 갱신한 뒤 검증하세요. 현재 그래프 모델의 범위는 Service 간 `depends_on`과 초기 `about`입니다. 담당 팀·API·운영 조건은 원문 검색으로 답합니다.

## LLM 선택

```sh
python3 serve.py --cli agy
python3 ask.py "질문" --cli claude
python3 ask.py "질문" --cli codex
```

`cursor-agent`, `copilot`도 기존 교시의 CLI 어댑터를 지원합니다. 추가 인자는 `--cli-arg=--model --cli-arg=모델명`처럼 전달합니다. Codex는 내부에서 `exec`와 읽기 전용 모드로 연결합니다. 실제 통합 검증은 현재 로그인된 `agy`로 수행합니다. CLI는 JSON 본문을 반환해야 합니다. 로그인·설치 문제는 `runs/<실행 ID>/llm-*/transport/*/stderr.txt`를 확인하세요.

## 검증

```sh
python3 -m unittest discover -s tests -v
```

테스트는 실제 PyreWire로 네 스냅샷·경로 방향을 검증하며, 인용·미승인 사실·도구 제한·대화 전달·원문 보존도 확인합니다. 프로토콜 오류 테스트에는 제어된 테스트 모델을 사용하고, 실제 LLM 실행과 구분합니다. 현재 13개 테스트와 실제 `agy` 질문 4개(영향 경로, 담당 팀, 후속 정책 질문, S2/S3 비교)를 검증했습니다. [실제 답변 예시](examples/README.md)와 [검증 기록](verification.json)을 확인하세요. 자료 변경 후 서버를 재시작하면 다시 읽습니다.
