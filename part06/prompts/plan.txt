6교시의 input.json, evidence_bundle.json, comparison.csv와 제공 원문을 대조하여 검색 기록을 작성하라.
search_plan.md에 저장할 한국어 Markdown 본문만 출력하고, 첫머리에 LLM 생성 초안·사람 검토 대기임을 표시하라. 실습 중 검토할 수 있도록 80줄 이내로 요약하고, 근거 묶음과 비교 CSV의 전문을 반복하지 마라.

1. input.json에서 스냅샷, 후보 집합, 초기 문서 목록을 읽어 표로 기록하라. 후보별 초기 about 연결은 candidate_doc의 [서비스 ID, 문서 ID] 행만으로 판단하라. 해당 후보의 행이 없으면 초기 about 연결 없음으로 적되 후보에서 제거하지 마라. 원문 본문에 서비스가 언급된 것은 내용상 관련성이며 about 연결을 뜻하지 않는다. candidate_doc 자체가 입력에 없으면 연결 여부는 미확인으로 남겨라.
2. 근거 묶음의 expanded_doc_ids와 expansion_reason을 초기 문서의 실제 참조와 대조하라. 출발 문서·절 → 추가 문서·버전, 확장 이유를 기록하라. 초기 문서와 후속 탐색 문서를 섞지 마라. 제공 자료로 확인할 수 없는 확장은 미확인으로 표시하라.
3. 설계 이유, 운영 조치의 조건·범위·승인, 관측 시간의 의미에 관한 질문별로 실제 찾은 원문 절과 확인한 내용을 정리하라. 문서의 수치를 먼저 확인하고 그 수치가 설명하는 사건과 적용 범위를 기록하라.
4. 비교 CSV의 각 판정을 원문과 다시 대조하고 근거 부족·과잉 해석·수정이 필요한 내용을 기록하라. 근거 묶음의 gaps와 현재 자료의 한계를 바탕으로 후속 확인에 필요한 증거를 적어라.

원문은 [문서 ID 버전 §절](raw/실제파일명.md)로 연결하라. 따옴표 인용은 해당 절의 연속 문자열을 그대로 사용하고, 표를 재구성하거나 요약한 내용에는 인용부호를 붙이지 마라. 이 기록은 제공 자료를 대조해 작성한 탐색 요약이다. 실제 도구 호출 로그나 검색 시각을 꾸며내지 말고, 사람이 검토하거나 승인했다고 쓰지 마라.
