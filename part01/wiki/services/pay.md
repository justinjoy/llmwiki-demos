# pay 서비스

## 역할·소유
- **서비스 역할**: 직영몰 카드 결제 주문 건에 대해 주문 서비스(`order`)의 요청을 받아 PG 승인(`POST /v1/payments/authorize`)을 동기로 처리하고, 승인 완료 후 원장 서비스(`ledger`)에 결제 내역(`POST /v1/journal-entries`)을 동기 기록하며 결제 확인, 대사 및 재처리를 담당함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [order 위키](./order.md)).
- **처리 제외 범위**: 월말 후불 정산과 협력사 직배송은 결제 서비스 처리 범위에 포함되지 않고 별도로 처리함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
- **운영 소유팀**: 결제정산팀에서 결제 서비스와 원장 서비스를 운영함 ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).
- **장애 대응 담당**: 야간 장애 발생 시 SRE 당직자가 먼저 확인하며, 결제 내역 수정 또는 재처리가 필요한 경우 결제정산팀 당직자에게 연락함 (현재 특정 당직자 및 연락처는 당직표에서 확인해야 하며 추측하지 않음) ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).

## 직접 API
- **`POST /v1/payments/authorize` (결제 승인 요청)**
  - **호출 주체 및 시점**: 주문 서비스(`order`)가 재고 예약과 견적 유효기간을 확인한 뒤 결제 서비스(`pay`)를 동기 호출함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [order 위키](./order.md)).
  - **타임아웃 기준**: 3초 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **식별자 전달**: 장애 추적을 위해 쇼핑몰에서 생성한 요청 ID를 주문·결제 서비스에 함께 전달받음 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름)).
  - **처리 결과**: 승인 성공 시 결제 완료 응답을 반환하여 주문 서비스가 주문을 확정(`CONFIRMED`)하고 출고 시스템에 전달하도록 함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항)).
- **`POST /v1/journal-entries` (원장 기록 요청 - 원장 서비스 호출)**
  - **호출 주체 및 시점**: 결제 서비스(`pay`)가 PG사의 승인 응답을 받은 뒤 원장 서비스(`ledger`)를 동기 호출함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **타임아웃 기준**: 1.8초 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **기록 항목**: 결제 ID(`payment_id`), 가맹점 ID(`merchant_id`), 금액, 통화, 승인 번호 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **중복 검증 및 오류 처리 규칙**:
    - 결제 ID(`payment_id`)와 전표 유형(`entry_type`)의 조합으로 중복 기록을 확인함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
    - 동일한 결제 ID와 전표 유형으로 같은 요청이 다시 들어오면 기존 처리 결과를 반환함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
    - 결제 ID와 전표 유형이 같은데 금액이 다르면 오류로 처리함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).

## 오류 상태
- **승인 실패 및 PG 응답 지연/미수신**
  - **상태 및 처리**: PG 승인이 거절되거나 결제 승인 요청(`POST /v1/payments/authorize`) 응답이 3초 타임아웃을 초과하여 미수신된 경우, 주문 상태를 '결제 확인 중'(`PAYMENT_PENDING`)으로 유지하고 미결제 주문이 출고되지 않도록 함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [order 위키](./order.md)).
  - **재결제 방지 및 확인 지침**: 고객 구매 화면에 '결제 확인 중'을 표시하며, 새로고침이나 재시도 시에도 신규 결제를 다시 요청하지 않고 기존 주문 번호/결제 ID로 승인 내역 및 처리 상태를 조회함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항)).
  - **재처리 주체**: 각 서비스에서 독립적으로 자동 재시도하지 않으며, 결제 서비스에서 승인 내역 확인 및 재처리를 담당함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
- **원장 응답 지연**
  - **상태 및 처리**: PG 승인은 완료되었으나 원장 기록 요청(`POST /v1/journal-entries`)이 1.8초 타임아웃을 초과하거나 원장 저장이 지연된 경우, 해당 결제를 '원장 반영 대기'(`LEDGER_PENDING`) 상태로 저장하고 대사 큐(Reconciliation Queue)에 등록함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 3. 후속 작업](../../raw/ADR-07_v1.md#3-후속-작업), [INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
  - **대사 및 재처리 절차**: 대사 작업은 PG 승인 내역과 원장 기록을 비교한 뒤, 신규 결제 승인을 요청하지 않고 기존 결제 ID(`payment_id`)로 재처리를 수행함 ([ADR-07 v1 3. 후속 작업](../../raw/ADR-07_v1.md#3-후속-작업), [INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).

## 사고
- **2026-08-18 카드 결제 주문 완료 지연 ([INC-03 v1](../incidents/INC-03.md))**
  - **개요 및 원인**: 2026년 8월 18일 09:42~10:07에 결산 사전 집계 배치가 넓은 범위의 원장 데이터를 잠그면서 DB 연결 풀 소진 및 원장 쓰기 지연(p95) 경보가 발생함. 결제 서비스의 원장 호출이 1.8초 타임아웃을 초과하면서 카드 결제 주문 4,900건 중 186건의 주문 확정이 지연됨 ([INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요), [INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치)). 로그상 네트워크 단절 징후는 없었음 ([INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치)).
  - **과거 조치 대상 및 대응 내역**:
    - **조치 대상**: 대상 가맹점 목록 확인 후 해당 대상 가맹점의 결제 대사 작업을 일시 중지함 (원장 조회 및 재처리 대기 누적 방지 목적) ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - **운영 유지**: 대사 작업 중지 중에도 PG 승인 API는 계속 정상 운영함 ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - **배치 중단**: 09:54 결산 사전 집계 배치를 중지하여 대기 요청을 감소시킴 ([INC-03 v1 3. 타임라인](../incidents/INC-03.md#3-타임라인)).
    - **고객센터 안내**: 고객센터에 재결제를 안내하지 말고 기존 주문의 처리 상태를 확인하도록 안내 공유함 ([INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
  - **승인 조건 및 재처리 결과**:
    - 결제 ID별 PG 승인 내역과 원장 기록을 대조하여, **승인 결과가 확인된 건부터 기존 결제 ID로 재처리**를 진행함 ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - **승인 결과가 확인되지 않은 건은 보류** 처리함 ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - 대사 과정에서 신규 결제 승인을 요청하지 않았음 ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - 10:24 지연 주문 186건에 대한 대사를 완료하였으며, 중복 승인 및 중복 원장 기록은 발생하지 않았음 ([INC-03 v1 3. 타임라인](../incidents/INC-03.md#3-타임라인)).

- **RUN-02 v1 (주문 완료 알림과 주문 상태 조회)**: 운영 문서의 상세 내용 및 연계 명세 확인 필요 ([ARCH-01 v1 4. 관련 문서와 변경 이력](../../raw/ARCH-01_v1.md#4-관련-문서와-변경-이력)).
- **진행 예정 후속 조치 완료 여부 및 향후 일정**: 결제정산팀의 '배치 처리 단위 분할 및 동시 실행 수 제한' 및 SRE의 'DB 연결 대기와 API 응답 지연 경보 분리' 과제의 향후 최종 완료/복구 시점은 입력 문서에 기술되어 있지 않으며 추측하지 않고 후속 확인 대상으로 지정함 ([INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치)).
- **현재 당직자 정보**: 야간 장애 시 연락할 결제정산팀 당직자 및 연락처는 당직표에서 직접 확인해야 함 ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).
