# order 서비스

## 역할·소유
- **서비스 역할**: 직영몰 카드 결제 주문 접수 시 재고 예약과 견적 유효기간을 확인한 뒤 결제 서비스(`pay`)의 승인 요청(`POST /v1/payments/authorize`)을 동기로 호출하고, 결제 완료 응답 수신 후 주문을 확정(`CONFIRMED`)하여 출고 시스템에 전달함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [pay 위키](./pay.md)).
- **처리 제외 범위**: 월말 후불 정산과 협력사 직배송은 주문 서비스 처리 흐름에 포함되지 않고 별도로 처리함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
- **운영 소유팀**: 커머스플랫폼팀에서 쇼핑몰 서버(`shop`)와 주문 서비스(`order`)를 운영함 ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).
- **장애 대응 담당**: 야간 장애 발생 시 SRE 당직자가 먼저 확인하며, 결제 내역 수정 또는 재처리가 필요한 경우 결제정산팀 당직자에게 연락함 (현재 특정 당직자 및 연락처는 당직표에서 직접 확인해야 함) ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).

## 직접 API
- **`POST /v1/orders` (주문 접수 API)**
  - **호출 주체 및 시점**: 쇼핑몰 서버(`shop`)가 고객의 주문서 접수 시 주문 서비스(`order`)를 호출함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름)).
  - **타임아웃 기준**: 5초 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **타임아웃 시 처리**: 응답 미수신 또는 타임아웃 발생 시 기존 주문 번호로 처리 상태를 조회함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).
  - **식별자 전달**: 장애 추적을 위해 쇼핑몰에서 생성한 요청 ID를 주문·결제 서비스에 함께 전달함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름)).
  - **내부 처리 과정**:
    - 재고 예약과 견적 유효기간을 확인한 뒤 결제 서비스(`pay`)의 `POST /v1/payments/authorize`를 동기로 호출함 (타임아웃 3초) ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [pay 위키](./pay.md)).
    - 결제 완료 응답을 받으면 주문을 확정(`CONFIRMED`)하고 출고 시스템에 전달함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항)).

## 주문 상태
- **주문 확정 (`CONFIRMED`)**
  - **전이 조건**: 결제 서비스(`pay`)로부터 결제 완료 응답을 수신한 후 주문을 확정함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항)).
  - **후속 처리**: 확정된 주문만 출고 시스템에 전달함 ([ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항)).
- **결제 확인 중 (`PAYMENT_PENDING`)**
  - **전이 조건**: 결제 서비스(`pay`) 호출 후 3초 타임아웃 내에 응답을 받지 못하거나 결제 응답이 늦어지는 경우 주문을 '결제 확인 중' 상태로 유지함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [pay 위키](./pay.md)).
  - **화면 처리 및 재시도 제한**: 구매 화면에 '결제 확인 중'을 표시하며, 새로고침 시에도 결제를 다시 요청하지 않고 기존 주문 번호로 처리 상태를 조회함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).
  - **재처리 주체**: 각 서비스에서 독립적으로 자동 재시도하지 않으며, 결제 서비스에서 확인과 재처리를 담당함 ([ARCH-01 v1 2. 결제 내역 기록과 타임아웃](../../raw/ARCH-01_v1.md#2-결제-내역-기록과-타임아웃)).

## 결정 이유
- **선(先) 주문 확정 및 후(後) 결제 처리 검토안의 문제점** ([ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)):
  - 주문을 먼저 확정하고 결제를 나중에 처리하면 고객에게 빠르게 주문 완료 화면을 보여줄 수 있는 장점이 있음 ([ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).
  - 그러나 이후 카드 승인이 거절될 경우 출고 요청을 취소하고 확보해 둔 재고를 풀어줘야 함 ([ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).
  - 특히 이미 출고가 진행된 주문은 자동 취소가 어려워 운영팀의 수작업이 필요해짐 ([ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).
- **결제 승인 후 주문 확정 방식 채택 이유** ([ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)):
  - 결제 결과를 확인한 뒤 주문을 확정하는 방식을 채택함으로써, 결제 응답 지연 시 주문 완료는 늦어지지만 미결제 주문이 출고되는 문제를 방지함 ([ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).
  - 결제 응답이 오지 않는 지연 시에는 재결제를 유도하지 않고 기존 주문 번호로 상태를 조회하도록 화면 및 시스템을 처리함 ([ARCH-01 v1 1. 주문 처리 흐름](../../raw/ARCH-01_v1.md#1-주문-처리-흐름), [ADR-07 v1 1. 결정 사항](../../raw/ADR-07_v1.md#1-결정-사항), [ADR-07 v1 2. 검토 내용](../../raw/ADR-07_v1.md#2-검토-내용)).

## 사고
- **2026-08-18 카드 결제 주문 완료 지연 ([INC-03 v1](../incidents/INC-03.md))**
  - **사고 개요 및 영향**: 2026년 8월 18일 09:42~10:07 동안 원장 쓰기 지연으로 결제 서비스의 원장 호출 1.8초 타임아웃이 초과되면서, 카드 결제 주문 4,900건 중 186건의 주문 확정이 지연되어 '결제 확인 중' 상태에 머무름 ([INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요), [INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치), [pay 위키](./pay.md)).
  - **집계 및 영향 범위**: 주문 번호 기준으로 집계(화면 반복 조회 제외)했으며, PG 승인은 완료됐으나 원장 기록이 늦어진 건도 포함됨. 월말 후불 정산은 영향 범위에 포함되지 않음 ([INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
  - **고객센터 공유 지침**: 장애 발생 당시 고객센터에는 재결제를 안내하지 말고 기존 주문의 처리 상태를 확인하도록 공유함 ([INC-03 v1 1. 장애 개요](../incidents/INC-03.md#1-장애-개요)).
  - **대응 타임라인 및 결과**:
    - 09:49 대상 가맹점 결제 대사 일시 중지 (PG 승인 API는 지속 운영) ([INC-03 v1 2. 대응 내역](../incidents/INC-03.md#2-대응-내역)).
    - 09:54 결산 사전 집계 배치 중지로 대기 요청 감소 ([INC-03 v1 3. 타임라인](../incidents/INC-03.md#3-타임라인)).
    - 10:07 신규 주문 처리 시간 정상화 (신규 주문 지연은 25분간 지속) ([INC-03 v1 3. 타임라인](../incidents/INC-03.md#3-타임라인)).
    - 10:24 지연 주문 186건 대사 완료 (중복 승인 및 중복 원장 기록 없음, 경보 발생부터 42분 소요) ([INC-03 v1 3. 타임라인](../incidents/INC-03.md#3-타임라인)).
  - **과거 사고와 현재 운영 상태 구분**:
    - 본 장애는 2026-08-18에 발생한 과거 일시적 장애 사건이며, 현재 주문 서비스 운영 구성은 2026-08-12 배포분 기준을 따르고 있음 ([ARCH-01 v1 4. 관련 문서와 변경 이력](../../raw/ARCH-01_v1.md#4-관련-문서와-변경-이력)).

## 미확인
- **RUN-02 v1 (주문 완료 알림과 주문 상태 조회)**: 주문 완료 알림 및 주문 상태 조회를 명시한 운영 문서 RUN-02 v1의 상세 내용 및 연계 명세는 원문에 없으므로 미확인으로 남김 ([ARCH-01 v1 4. 관련 문서와 변경 이력](../../raw/ARCH-01_v1.md#4-관련-문서와-변경-이력)).
- **출고 단계별 취소 가능 범위**: ADR-07 v1 후속 작업으로 지정된 커머스플랫폼팀의 '출고 단계별 취소 가능 범위 정리' 과제의 상세 내용 및 완료 여부는 원문에 명시되지 않음 ([ADR-07 v1 3. 후속 작업](../../raw/ADR-07_v1.md#3-후속-작업)).
- **ARCH-01 v2 (원장 기록 비동기 전환 검토안)**: 원장 기록 비동기 전환 및 비동기 결제 방식 검토안은 검토 중이며 배포 일정이 미정 상태임 ([ARCH-01 v1 4. 관련 문서와 변경 이력](../../raw/ARCH-01_v1.md#4-관련-문서와-변경-이력), [ADR-07 v1 3. 후속 작업](../../raw/ADR-07_v1.md#3-후속-작업)).
- **OPS-04 v1 (결제 대사 운영 절차)**: 결제 대사 작업 큐 중지 및 재개 절차를 명시한 OPS-04 v1 문서의 상세 내용은 제공된 원문에 포함되어 있지 않음 ([ADR-07 v1 3. 후속 작업](../../raw/ADR-07_v1.md#3-후속-작업), [INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치)).
- **INC-03 후속 조치 완료 여부**: 결제정산팀의 배치 처리 단위 분할 및 동시 실행 수 제한, SRE의 DB 연결 대기/API 응답 지연 경보 분리 과제의 현재 진행 완료 여부 및 향후 일정은 원문에 기술되어 있지 않음 ([INC-03 v1 4. 원인과 후속 조치](../incidents/INC-03.md#4-원인과-후속-조치)).
- **현재 당직자 정보**: 야간 장애 시 연락할 커머스플랫폼팀 및 결제정산팀 당직자와 연락처는 당직표에서 직접 확인해야 함 ([ARCH-01 v1 3. 운영 담당](../../raw/ARCH-01_v1.md#3-운영-담당)).
