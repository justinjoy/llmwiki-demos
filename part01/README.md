# 1교시 · LLMWiki 구축과 지식 탐색

이 폴더만으로 실행할 수 있는 1교시 데모입니다. Python 3.9 이상과 로그인된 LLM CLI가 필요합니다. Wirelog 설치는 필요하지 않습니다.

## 시작

프로젝트 루트의 터미널에서 실행합니다.

```sh
cd demos/part01
python3 run_lesson1.py --cli agy --task pay --dry-run
python3 run_lesson1.py --cli agy --task pay --overwrite
```

첫 명령은 문서를 나누고 청크별 실제 입력을 생성합니다. 두 번째 명령은 청크마다 LLM을 호출해 근거를 추출하고, 그 근거로 `wiki/services/pay.md`를 작성합니다. 기존 내용은 모든 단계가 성공한 뒤 `runs/`에 백업합니다. 최종 작성 입력은 청크별 응답을 받은 뒤 구성하므로 dry-run에는 없습니다.

`--cli`는 `agy`(Antigravity), `claude`, `cursor-agent`, `copilot`, `codex`로 바꿀 수 있습니다. Codex는 내부에서 `exec`로 연결합니다. [상세 실행 안내](CLI_GUIDE.md)를 참고하세요.

## 실습 순서

실습 A는 서비스 위키 생성과 검토, 실습 B는 장애 위키와 링크 탐색입니다. 각 실행 후 생성 내용을 원문과 대조하고 다음 단계로 진행하세요.

```sh
# 실습 A: pay를 검토한 뒤 order 생성
python3 run_lesson1.py --cli agy --task order --overwrite

# 실습 B
python3 run_lesson1.py --cli agy --task incident --overwrite
python3 run_lesson1.py --cli agy --task index --overwrite
python3 run_lesson1.py --cli agy --task explore --overwrite
python3 run_lesson1.py --cli agy --task log --overwrite
python3 check_links.py wiki
```

강사 시연에서 6단계를 연속 실행하려면 아래 명령을 사용합니다. 중간 실패 시 이후 단계는 실행하지 않습니다.

```sh
python3 run_lesson1.py --cli agy --task all --overwrite
```

## 문서를 나눠 읽는 방법

호출 수를 줄이기 위해 작업 전체의 원문과 앞 단계 위키를 **최대 3개 청크**로 묶습니다. 파일이나 절마다 호출하지 않습니다.

1. 전체 입력이 초기 프롬프트 목표 안에 들어가면 청크 하나로 읽습니다. 필요할 때만 균형 잡힌 2개·3개 청크를 검토합니다. 청크는 여러 파일의 원문 조각을 포함할 수 있습니다.
2. 각 조각의 파일명·해시·원문 범위·행 번호·원문/파생 구분을 유지합니다. 머리말도 원래 위치에서만 전달하며 다른 조각에 반복하지 않습니다. 모든 입력 문자는 한 번씩 포함됩니다.
3. 모델은 각 인용에 `source_id`를 붙입니다. 실행기는 현재 청크의 해당 조각 안에 인용이 정확히 존재하는지 검사합니다. 근거는 청크당 최대 6개이며, 설명은 각각 300자 이하입니다.
4. 검증된 근거 **전부**를 최종 작성 한 번에 전달합니다. 근거를 줄이기 위한 별도 LLM 호출이나 추출 후 크기 때문에 제외하는 과정은 없습니다.

일반 호출 수는 작업당 **청크 읽기 1~3회 + 최종 작성 1회**입니다. JSON·인용·최종 형식 검증에 실패하면 같은 입력으로 한 번만 교정 요청하고 재검증합니다. 이 요청도 전체 호출 수에 포함됩니다. 실패한 응답의 근거는 사용하지 않습니다.

`pay`, `order`, `incident`, `index`, `explore`, `log`에 같은 방식을 적용합니다. 앞 단계 위키는 `derived`(생성 초안)로 표시하며 원문 사실로 자동 승인하지 않습니다.

### 진행 상황 표시

시작할 때 청크 수와 요청한 본문 크기·실제 최대 크기를 표시합니다. 각 청크에 포함된 파일·절 범위·원문 행 번호를 나열하고, 검증이 끝나면 근거 수를 출력합니다.

```text
청크 1개 / 본문 목표 4800자 → 실제 최대 4122자 / 실행 기록: …
[청크 1/1] 읽는 중: 출처 조각 3개
  raw/ARCH-01_v1.md · # 직영몰 주문·결제 시스템 구성 … ## 4. 관련 문서와 변경 이력 (원문 1~48행)
…
[청크 1/1] 완료 · 근거 6개
[최종 작성] 근거 6개로 pay.md 작성 중
```

위 숫자는 표시 예시입니다. `--dry-run`에서는 `[청크 1/1] 입력 준비`로 표시하며 CLI를 호출하지 않습니다. 최종 입력은 실제 근거 응답 후 구성합니다.

### 크기와 호출 수

```sh
python3 run_lesson1.py --cli agy --task pay --chunk-chars 4800 --max-prompt-chars 16000 --max-calls 256 --overwrite
```

- 본문 크기의 초기 목표는 기존 800자의 6배인 **4,800자**입니다. 작은 청크를 늘리는 대신 입력 분량과 호출 수에 맞춰 실제 크기를 자동 조정합니다. 이 값보다 작은 조각을 만들기 위해 청크 수를 늘리지는 않습니다.
- `--max-prompt-chars`의 기본 16,000자는 **초기 목표**입니다. 공통 지침·과제·메타데이터·중첩 JSON과 교정 여유를 포함해 실제 입력을 측정합니다. 3개 청크나 최종 근거가 목표를 넘으면 필요한 크기로 확대하고 `[입력 크기 조정]`을 출력합니다. 과거의 고정 상한과 의미가 다릅니다. 문자 수이며 모델별 토큰 수가 아닙니다.
- `manifest.json`의 `requested_chunk_chars`, `requested_prompt_chars`, `effective_chunk_chars`, `effective_prompt_chars`와 호출별 `prompt_chars`로 조정을 확인합니다. 각 작업은 원래 요청한 목표로 새로 계획합니다.
- 입력 파일 합계 1 MiB, 호출별 응답 16,000 bytes, 문서 머리말 800자·절 제목 300자 제한은 유지합니다. 모델이나 OS가 큰 입력을 받지 못하면 CLI 오류가 날 수 있습니다. 자동 크기 조정이 외부 모델의 문맥 한도를 보장하지는 않습니다.
- 기본 전체 호출 예산은 256회이며 `--task all`과 모든 교정 요청이 공유합니다. 최대 3개는 작업별 **최초 읽기 청크 수**이며 교정 요청·최종 작성 횟수와 구분합니다.
- JSON·인용·최종 형식 검증은 한 번 교정 후에도 실패하면 중단합니다. CLI 실패·시간 초과, 응답·파일·호출 예산 초과도 중단합니다. 해당 작업의 기존 결과는 보존하며, 이미 성공한 앞 단계 결과는 남습니다.
- JSON 앞 설명문 뒤에 독립된 객체가 하나만 있으면 읽습니다. 설명문에 중괄호·대괄호가 있거나 여러 객체·JSON 뒤 설명이 있으면 경계가 모호하므로 거부합니다. 객체도 동일한 출처·형식 검사를 통과해야 합니다.

모든 원문을 전달해도 청크당 추출 근거는 최대 6개이므로 모든 사실을 추출했다는 뜻은 아닙니다. 추출된 근거는 모두 최종 입력에 전달하지만 최종 문서가 모든 근거를 정확히 설명한다고 자동 승인하지 않습니다. 사람의 원문 대조가 필요합니다.

## 다른 파일에도 청킹 적용

`-p`로 프롬프트 파일, `-c`로 원문 파일, `-o`로 결과 파일을 지정합니다.

```sh
python3 chunk_pipeline.py --cli agy -p prompt.txt -c raw/ARCH-01_v1.md -c raw/ADR-07_v1.md -c raw/INC-03_v1.md -o wiki/services/pay.md --overwrite
```

## 파일과 제출물

- `raw/`: 아키텍처·설계 결정·장애 보고서 원문 3개. 교육용 합성 사례입니다.
- `prompt.txt`, `prompts/`: 단계별 프롬프트.
- `wiki/`: 서비스·장애 페이지, 탐색 입구, 변경 기록.
- `exploration.csv`: 세 질문의 답과 탐색 경로·근거.
- `review.md`: 수강생이 직접 작성할 검토·수정 기록.
- `chunk_pipeline.py`: 통합 청크 계획·출처 검증·크기 자동 조정·최종 저장.
- `run_prompt.py`: 개별 CLI 호출을 담당하는 하위 실행기. 직접 호출하면 청킹하지 않습니다.
- `runs/chunk-*/manifest.json`: 청크별 출처 원문·위치·해시, 요청/실효 크기, 단계·교정 횟수·호출 수, 성공·실패 상태.
- `runs/chunk-*/evidence.json`: 전체 검증 근거. `summary.txt`: 청크·근거 수와 검토 상태. `previous.md` 또는 `previous.csv`: 기존 결과 백업.
- `runs/chunk-*/*/transport/*/`: 실제 `input.txt`, `stdout.txt`, `stderr.txt`, `run.json`. 실행할 때 생성됩니다.

위키의 출처와 상대 링크를 검토하세요. 25분·42분은 과거 사고의 관측값이며 미래 복구 보장이 아닙니다. 생성한 답변과 변경 기록은 사람 검토 전의 초안입니다.

정답 예제는 이 데모에 포함하지 않았습니다.
