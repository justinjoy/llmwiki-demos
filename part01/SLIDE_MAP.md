# 1교시 슬라이드와 데모 연결

[최종 슬라이드](../../slides/part01.pptx) · [실행 안내](README.md)

| 슬라이드 | 제목 | 확인할 내용 |
| --- | --- | --- |
| 1 | LLMWiki 구축과 지식 탐색 | LLMWiki는 LLM이 업무 문서를 읽고 주제별 설명 페이지와 링크를 만드는 방식입니다 |
| 2 | 학습 목표와 60분 진행 | 완성할 것은 order·pay·INC-03 페이지와 탐색 기록입니다 |
| 3 | 공통 사례: 기업용 소모품 주문 | 고객이 주문하면 카드 승인을 확인한 뒤 주문을 확정하고 출고로 넘깁니다 |
| 4 | 원문과 위키의 역할 | 원문은 처음 작성된 업무 기록이고 위키는 그 기록을 찾아 읽기 쉽게 정리한 설명입니다 |
| 5 | 첫 번째 원문 묶음 | 원문 세 개의 제목·버전·상태·적용 범위를 확인합니다. 청크에도 문서 정보·절·원문 위치를 붙입니다 |
| 6 | 위키의 최소 폴더 구조 | raw에는 원문을 보관하고 wiki에는 설명 페이지를 둡니다 |
| 7 | 위키 페이지의 공통 형식 | 페이지에는 서비스가 하는 일, 담당 팀, 다른 서비스에 보내는 요청을 씁니다 |
| 8 | 시연: 문서를 나눠 pay 페이지 생성 | 원문을 800자 이하 청크로 나눠 근거를 추출합니다. 근거가 크면 묶음별로 선택하고 위키를 작성합니다 |
| 9 | 위키 생성 프롬프트 | `prompt.txt` 1~7행 발췌(전체 10행은 노트). `run_lesson1.py --task pay`가 `chunk_pipeline.py`의 청크별 추출·근거 선택·최종 작성을 실행합니다. 각 호출은 `run_prompt.py`로 전달합니다 |
| 10 | 실습 A: 서비스 위키 생성 | 청크별 근거와 사용·제외 개수를 확인합니다. pay 페이지를 검토한 뒤 order 페이지를 만듭니다 |
| 11 | 실습 A 확인: 사실과 적용 범위 | 186건은 주문 확정이 늦어진 건수이며 전부 승인 실패라는 뜻이 아닙니다 |
| 12 | 실습 B: 링크를 따라 근거 탐색 | INC-03 사고 페이지와 index를 만들고 order 페이지에서 사고 원문까지 링크를 따라가 봅니다 |
| 13 | 실습 B 확인: 답과 근거 | 25분은 경보부터 신규 주문 처리가 정상화될 때까지이고, 42분은 보류된 주문의 결제 기록 확인을 마칠 때까지입니다 |
| 14 | 자주 생기는 위키 오류 | 서비스 이름이 조금 다르다고 페이지를 중복 생성할 수 있고, 실제로 없는 파일을 링크할 수도 있습니다 |
| 15 | 확인 문제 | 첫 질문은 과거의 복구 기록을 미래의 약속으로 바꿔도 되는지 묻습니다 |
| 16 | 확인 문제 해설 | 경보는 09:42, 신규 주문 정상화는 10:07, 보류 주문의 결제 기록 확인 완료는 10:24입니다 |
| 17 | 이번 시간의 산출물 | 세 페이지와 링크, 세 질문의 답과 출처, 실제 검토 기록을 제출합니다 |
| 18 | LLMWiki와 Wirelog 실습 과정 | 다음 시간의 온톨로지는 업무에서 다룰 대상의 종류와 서로 연결하는 방법을 정한 약속입니다 |
