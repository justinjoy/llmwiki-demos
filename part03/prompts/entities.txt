원문과 앞 단계 후보·별칭 결과를 대조하여 개체와 속성을 추출하라.
entities.json에 저장할 JSON 객체만 반환하라. 최상위 키는 services, apis, excluded_from_service_graph이며 값은 모두 배열이다.

1. assertions.jsonl에서 추출된 호출 주체·대상을 원문과 다시 대조하여 현재 운영 중인 직접 호출 경로의 서비스를 찾고 services에 기록하라. aliases.json은 정규화의 단서이며 명시적 원문 근거를 확인한 별칭만 적용하라. 이전 LLM 결과를 사실의 근거로 대신 사용하지 마라.
2. 운영 담당 절에서 각 서비스의 담당 팀을 찾고, 문서 작성 담당 팀·API 제공 서비스·호출 서비스·실제 당직자 개인을 구분하라. 현재 당직자나 연락처를 만들어내지 마라.
3. 원문의 호출 설명과 API 표에서 각 직접 호출의 메서드·경로·제공 서비스·호출 주체·해당 구간의 타임아웃을 찾아 apis에 기록하라. 서비스 ID(id, owner_service, caller)는 후보와 같은 표준 ID를 사용하며 svc: 접두사를 붙이지 마라. timeout_seconds는 해당 caller→API 구간의 값이며 모든 API의 공통 제한 시간이 아니다.
4. 용어집과 타입 정의를 대조하여 Service 호출 그래프에 포함할 수 없는 저장소·배치 개체를 찾아 excluded_from_service_graph에 기록하라. 이름의 공통 접두사를 근거로 서비스와 합치지 마라.
5. 문서의 상태·적용 대상·배포 여부를 확인하여 검토안의 API·이벤트·워커를 현재 운영 개체로 확정하지 마라. 원문에 없는 속성은 추측으로 채우지 마라.

출력 스키마
- services의 항목: id, type, owner_team, source_id, version, section, quote.
- apis의 항목: id, type, owner_service, method, path, caller, timeout_seconds, source_id, version, section, quote.
- excluded_from_service_graph의 항목: id, type, reason, source_id, version, section, quote.
type은 Service, API, DataStore, BatchJob 중 원문과 정의에 맞는 값을 사용한다. API의 id는 api:소유서비스:HTTP메서드:경로 형식의 수업용 식별자이고 timeout_seconds는 문자열이 아닌 JSON 숫자다.
source_id는 실제 문서 번호만, version은 실제 버전을 별도로 기록하고 section은 "§번호" 형식으로 쓴다. 각 quote는 해당 절의 연속 문자열로서 그 항목의 담당 팀·호출 구간·타입 등 기록한 속성을 뒷받침해야 한다. 서로 떨어진 문장을 이어 붙이거나 생략 표시를 넣지 마라.
