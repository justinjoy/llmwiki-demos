제공된 업무 원문에서 현재 운영 기준의 내부 Service 간 직접 HTTP 호출을 추출하라.
ontology/types.csv와 ontology/relations.csv는 2교시 모델의 복사본이다. 관계의 포함·제외와 방향을 적용하라. 3교시 슬라이드에 맞춰 svc: 접두사를 제외한 표준 ID를 쓴다. 2교시에서 확인 보류한 이름은 이번 GLOSS-01 원문으로 확인한다.
출력은 assertions.jsonl에 저장할 JSONL 본문만 반환하라. 한 줄에 JSON 객체 하나이며 배열이나 코드 블록으로 감싸지 말라.
ARCH-01 v1의 주문 처리 순서대로 직접 호출 후보 3개를 F01, F02, F03으로 기록하라.
각 객체에 다음 필드를 모두 포함하라.
assertion_id, subject, predicate, object, subject_type, object_type, source_id, version, section, quote, document_status, scope, review_status, reviewer, snapshot_id
predicate는 depends_on, subject_type과 object_type은 Service로 쓴다.
subject와 object는 GLOSS-01에서 확인한 표준 서비스 ID를 사용한다.
source_id는 문서 번호, version은 v1 형식, section은 §1 같은 절 번호, quote는 그 절의 원문을 그대로 복사한 연속 문자열이다.
source_id에는 버전을 붙이지 말라. 예: "source_id":"ARCH-01", "version":"v1". "ARCH-01 v1"은 source_id로 허용하지 않는다.
원문에 없는 말이나 생략 기호를 quote에 추가하지 말라.
document_status는 원문 문서의 상태이고 review_status는 추출 결과의 검토 상태이므로 구분하라.
document_status는 한글 원문을 다음 코드로 변환하라: 승인 완료 → approved, 검토 중 → draft, 리뷰 완료 또는 검토 완료 → reviewed.
review_status는 반드시 pending, reviewer는 빈 문자열, snapshot_id는 S1이다.
scope에는 직영몰 카드 선결제와 내부 직접 HTTP 호출 범위를 적어라.
GLOSS-01로 별칭을 확인해도 간접 의존, DB, 배치 작업을 직접 서비스 호출로 만들지 말라.
ARCH-01 v2는 운영 미반영 검토안이다. 그 내용을 현재 직접 호출의 삭제 사실로 넣지 말라.
실제 승인과 파일 저장은 수강생과 실행 스크립트가 담당한다. 원문은 변경하지 말라.
