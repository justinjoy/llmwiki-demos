3교시: 현재 운영 기준의 내부 Service 간 직접 HTTP 호출을 원문에서 찾아라.

질문: 현재 운영 중인 내부 서비스들은 어떤 API를 통해 어느 방향으로 직접 호출하는가?

입력과 역할
- raw/*.md: 문서 상태·적용 대상·호출 관계·용어를 확인할 원문이다.
- ontology/types.csv, ontology/relations.csv: 타입과 관계의 정의·포함·제외 규칙이다. 사실 목록이나 추출 정답이 아니다.
실행 스크립트가 각 파일의 내용을 참고 파일(JSON)의 file/content로 제공한다. 제공된 내용 안에서 작업하고 외부 검색이나 파일 접근 도구를 호출하지 마라.

추출 절차
1. 문서의 번호·버전·상태·적용 대상과 배포 여부를 확인하여 현재 운영 구성의 근거를 선택하라. 최신 버전이라는 이유만으로 검토 중인 안을 운영 사실로 취급하거나 기존 호출이 삭제됐다고 해석하지 마라.
2. 운영 원문에서 직접 HTTP 호출을 명시한 문장과 API 표를 찾아 호출 주체, 호출 대상, 메서드와 경로를 확인하라. subject는 호출하는 서비스, object는 API를 제공하는 서비스다. 응답 반환을 반대 방향의 별도 호출로 만들지 마라.
3. 용어집에서 이름과 명시적 별칭을 확인하고 svc: 접두사 없는 표준 서비스 ID로 정규화하라. 이름이 비슷하다는 이유로 서비스·저장소·배치·배포 리소스를 합치지 마라. 문서에 언급됐어도 직접 호출 근거가 없으면 관계를 만들지 마라.
4. 관계 사전의 포함·제외 규칙을 적용하라. 간접 경로, 외부 시스템, DB 접속, 단순 동시 언급을 내부 Service 간 직접 HTTP 호출로 적재하지 마라.
5. 이 실습의 후보 목록에서는 같은 subject/predicate/object 관계를 중복 출력하지 마라. 여러 문서가 같은 관계를 설명하면 현재 운영 구성과 직접 API 호출을 가장 명확하게 설명하는 대표 근거를 선택하라. 대표 운영 문서에 나타난 업무 흐름·호출 설명 순서로 후보를 정렬하고 F01부터 F02, F03처럼 순번을 붙여라. 추출 개수는 원문 근거로 결정하고 특정 개수를 맞추려고 사실을 만들지 마라.
6. 출처의 실제 문서 번호·버전·절을 기록하고 호출 주체·대상·방향을 뒷받침하는 연속 문자열을 quote로 그대로 복사하라. 문장을 합성하거나 생략 표시를 넣지 마라. scope는 원문에서 확인한 업무 적용 대상과 직접 HTTP 호출이라는 추출 범위를 요약하라.
7. 문서 상태와 추출 결과의 검토 상태를 구분하라. 승인된 문서를 읽었어도 추출은 사람 검토 전 초안이며 실제 승인·검토자를 만들어내지 마라. 근거가 확인되는 후보만 출력하라.

출력 스키마
assertions.jsonl에 저장할 JSONL 본문만 반환하라. 한 줄에 JSON 객체 하나이며 배열이나 코드 블록으로 감싸지 마라. 각 객체는 다음 필드를 모두 포함한다.
- assertion_id: 위 순서로 부여한 F 접두사와 두 자리 이상 순번
- subject, object: 원문과 용어집으로 확인한 표준 서비스 ID
- predicate: "depends_on"
- subject_type, object_type: "Service"
- source_id: 원문의 문서 번호만 기록 (버전은 붙이지 않음)
- version: 실제 문서 버전인 "v번호"
- section: 실제 근거 절인 "§번호"
- quote: 해당 절에 실제로 존재하며 직접 호출 관계를 뒷받침하는 연속 문자열
- document_status: 원문 상태 코드. 승인 완료 → approved, 검토 중 → draft, 리뷰 완료 또는 검토 완료 → reviewed. 그 밖의 상태는 원문 그대로 기록한다.
- scope: 원문에서 확인한 업무 적용 범위와 내부 직접 HTTP 호출 범위의 한국어 요약
- review_status: "pending"
- reviewer: ""
- snapshot_id: "S1" (이 실습의 입력 식별자)
실제 파일 저장과 검토 상태 변경은 실행 스크립트와 수강생이 담당한다.
